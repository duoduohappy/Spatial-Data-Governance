# 0.6 升级：受控协作与范围规则

## 已实现的架构

输入原文/字典/表头 → 单次提议或可选双角色审查 → 证据编译 → 人工批准 → 唯一确定性内核 → 带范围的检查/整改/报告。

审查者可以决定查询原文行、某字段字典、某类规则契约，或结束审查。仅提供受控只读函数，无任意文件、HTTP、POI 记录值或批准工具。最多一轮工具查询、四次模型调用、一次提议修订；所有调用有角色标识，原始输出、工具请求与结果保留。当前真实合成工作台演示使用了两次模型调用、零次工具查询；有工具能力不冒充实际使用过工具。

`single` 为默认；`self_review` 保留提议时上下文；`dual_review` 从新的审查上下文读原文和提议，两者均用同一模型。原文与审查意见都不能越过系统约束。失败审查、遗漏、伪造引用、越权工具或超限不产生批准。审批依据数据库中的原始协作记录，删除编辑器里的 metadata 不能绕过确认。

一次修订后没有第二次模型复审，界面明确提示；人工仍须核对。新的任务记录持久化 strategy/mode，幂等键不能跨策略复用；旧数据库只从明确记录恢复 mode，无法确认时保留 legacy_unknown。

## 开发对照结果

第一轮暴露输出动作/字段组合未通过协议校验，拒绝了自检/双角色任务，保留失败记录。第二轮改为动作判别联合、按条款 ID 约束的检查对象后，三组各四份均完成。

第二轮：single 38/40、self_review 38/40、dual_review 37/40；三组各有一条缺失/冲突要求处理不正确，所有草案未批准，来源校验问题为零。实际 Token 分别 19,102 / 75,824 / 66,506。双角色未达到采用标准，默认不切换。

数据由实现方编写，第二轮已是暴露的开发回归，不是独立人工金标准。旧 80 条集合没有冒充新留出集。对照基于独立保存的源码快照；之后完善的范围输出约束、迁移、报告和 UI 不属于该次对照的源码，分别由新测试和真实工作台演示验证。

单次生成只调用一次，同角色/双角色都最多四次；报告实际使用量，不能称为相同实际 Token 预算。中途环境重置导致两次冷加载及一个未完成调用，其用量未知；不据此宣称稳定延迟优势或人工效率。

## 多实例的业务切口

先实现 freshness。同一声明的字符串枚举字段以互斥等值划分，例如 source=municipal 为 7 天、source=survey 为 30 天。范围必须来自绑定条款的显式正向标记 `仅对 field="value"`、`适用于 field="value"` 或 `For field="value"`；程序把该标记约束到输出 Schema，不是模型自由推断范围。其他表达、重叠范围、全局/局部混合、其他规则的范围暂不执行。

未知来源纳入不可解释记录，不静默排除；零匹配的实例保留 INDETERMINATE。每个实例有稳定 ID，findings 使用真实实例 ID。scope 进入整改尺子指纹；全量实体的来源字段变化进入待业务复核，即使新批次自身 PASS，也不能把移出原范围当成原缺陷已修复。目前没有自动批准重分类通道。

新输入示例 `examples/scoped_sources` 是未批准的合成材料。原六组冻结门禁输入/预期不变。HTML 与 JSON 都披露范围，页面展示候选、排除、未知来源数量。

## 试点与发布边界

POI 交付验收是已选方向；真实批次、业务审核人、独立标签和人工有效审核时间尚未取得。`docs/POI_PILOT.md` 与 `eval/pilot-template` 是待执行流程，不能写成已完成试点。

本轮是新分支上的升级候选，准备通过 PR 验证与审阅；以 acceptance/v06/STATUS.json 和实际 Actions 为准，0.5.x 的历史通过记录不代表新代码已经远程通过。
