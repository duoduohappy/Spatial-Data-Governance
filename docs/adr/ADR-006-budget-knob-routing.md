# ADR-006 预算旋钮 θ：由置信度触发的模型升级

- 状态：**降级为未来实验**（2026-10-26 修订）。**不再是 Stage 2 必做项**，不在首版（Stage 0–5 主线）范围内。
  修订原因：独立验收 GA-10 —— 本 ADR 重新引入"通用模型网关 + 置信度升级路由"，偏离首版范围，
  与 ADR-009（不自建通用网关）和《项目执行与验收方案 v1.0》的排除项冲突。
- 背景：单纯的"按任务类型静态路由"无法回答"贵调用值不值"，也无法在预算变化时给出稳定策略。
  该问题在首版中**不解决**，只做成本上限与记账。
- 决策（修订后保留的部分）：
  1. **预算上限与成本记录保留**：每次调用必须记录模型、token、延迟、费用、失败重试；
     超过预算即**暂停为未知或转人工**，**不静默降级**，也不得因为超预算而把未知改判为通过。
  2. **置信度升级路由与模型网关移出范围**：θ 旋钮、小模型→中大模型升级、跨厂商交叉验证
     均属**未来实验**，需要先有实测数据证明收益大于复杂度，否则不实现。
  3. **模型自报置信度不得作为路由可靠性证据，更不得用于放行批准。** 自报置信度只能作为
     risk signal（与"坐标量级"同级，见 `docs/stage0-recheck-contract.md` §0 A3 / §9.8），
     不参与任何 `verdict` 计算。
- 理由：首版的可信度来自"确定性工具 + 人工批准"，不来自模型路由策略；在没有任何实测数据的情况下
  把 θ 写进架构，会把未经证实的机制包装成已具备的能力。
- 后果：Stage 2 只需要"能记账、能设上限、能暂停"，不需要模型网关；
  `docs/architecture.md` 中的"模型网关 / 预算旋钮 θ"标注为未来实验，不进入主链路。
- 复审条件：**出现实测数据后**（而非 Stage 2 计划时间）才复审是否升级为正式特性；
  若 θ 分档的收益不超过额外复杂度，则维持"不实现"并如实记录。
- 相关：ADR-009（不自建通用网关）、ADR-010（判定授权公理：signal 不等于 evidence）。
