# 数据许可与来源清单（Stage 0）

负责人：用户　｜　维护时机：每次引入新数据来源前必须先更新本文件，再写代码实现。

## 一、当前使用的数据

| 数据集 | 来源 | 许可 | 可否再分发 | 处理 |
|---|---|---|---|---|
| examples/clean, defective, corrected, ambiguous, blocked | 由 `tools/make_examples.py` 生成 | 项目自有的合成数据，无第三方权利 | 可（随仓库分发） | 坐标与名称均为杜撰，不得与真实设施对应；README 中已注明为合成 |

**声明：Stage 0 未使用任何真实 POI、真实测绘成果、真实客户交付说明或真实数据字典。**
交付说明文本亦为便于验证而编写的示例文本，不代表任何单位的实际交付要求。

## 二、Stage 4 计划引入的公开数据（尚未获取，未入库）

| 候选来源 | 许可 | 约束 |
|---|---|---|
| OpenStreetMap 中国区某城市 extract | ODbL 1.0 | 必须标注来源；衍生数据库需同样许可；不得暗示背书 |
| 公开气象/地震站点名录 | 需逐个确认发布方条款 | 不确定则不用 |
| 其他公开 POI / 开放地理数据 | 逐个确认 | 不确定则不用 |

规则：
- 不可确认许可的数据一律不使用。
- 不可再分发的数据只提供获取脚本 + 版本/哈希，不落地到仓库。
- 使用真实数据前必须在本表登记，并在 README 与 THIRD_PARTY.md 中给出归属与许可链接。

## 三、不允许进入仓库的内容

- 真实客户的交付说明、数据字典、验收清单；
- 任何个人信息或可识别到个人的位置数据；
- API Key、Token、内网地址、账号信息；
- 未经脱敏的真实项目截图或报告。

## 四、第三方依赖许可

Stage 0 零第三方依赖（`tools/smoke_deps.py` 记录）。
Stage 1 引入依赖后需新增 `THIRD_PARTY.md`，逐个列出包名、版本、许可证与用途。
