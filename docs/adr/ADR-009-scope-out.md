# ADR-009 明确排除：通用网关、K8s、SSO、多租户

- 状态：已采纳
- 背景：范围蔓延是本类项目最常见的死法；"顺便做个网关"会把工期拖成不确定性。
- 决策：本阶段明确不做
  - 通用模型网关（LiteLLM / One-API 已覆盖；本项目只做 ADR-006 的路由策略，不重复造一层 URI 转发）；
  - K8s 编排、SSO、多租户、数据库 CDC、企业血缘；
  - 数据清洗平台能力（那是 Great Expectations / dbt 的地盘）。
- 理由：把这些排除项写下来，比"以后再说"更能保护项目；任何新增范围必须说明收益、工作量与验收影响。
- 后果：如果将来出现真实付费租户或私有化交付需求，需新增 ADR 并重新评估。
- 复审条件：出现明确的付费租户或合同要求时复审。
